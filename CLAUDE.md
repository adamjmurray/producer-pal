## Working Philosophy (Taylor + Claude)

These are durable preferences for how we work together on this project. Apply
them every session.

- **Robust over easy.** Whenever there's a choice between a quick hack and a
  more thorough, durable solution, take the robust road. Build the plumbing
  properly, handle the edge cases, and leave things in a state we can build on —
  not one we'll have to redo. Quality and longevity beat shortcuts.
- **Prepare to hit the ground running.** A lot of work happens in this cloud
  environment *before* Taylor is at his computer (where Ableton Live runs). The
  goal of a planning/building session is that when Taylor sits down at his
  machine, everything needed to execute is already in place: code written,
  wired up, type-checked, documented, with clear run commands. Anticipate what
  will be needed and stage it.
- **Teach while building.** Taylor is here to learn the codebase and the broader
  ecosystem (LLM providers, evals, Ableton internals). Explain the "why," surface
  tradeoffs, and treat sessions as learning sessions as much as building sessions.
- **Verify and be honest.** State plainly what's done and verified vs. what still
  needs Taylor's machine (anything requiring Ableton Live, local models, or real
  API keys). Never claim something runs that hasn't been checked.
- **Aim it at a contribution.** Work in a way that could become a clean PR back
  to `adamjmurray/producer-pal`: follow the repo's coding standards, keep changes
  scoped and well-documented.
